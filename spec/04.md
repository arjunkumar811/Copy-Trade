PHASE 2 — DATABASE MODEL

Implement the initial production database schema.

Create models/tables for:

users
wallets
followed_traders
copy_trade_settings
source_transactions
detected_trades
copy_trade_orders
trade_executions
audit_logs

Requirements:

- proper primary keys
- foreign keys
- unique constraints
- indexes
- created_at / updated_at
- status fields where required
- appropriate numeric types for financial values
- transaction-safe writes

Important:

Do not use floating point for money/token quantities where precision matters.

Design the schema so duplicate blockchain events cannot create duplicate copy trades.

For example, source transaction signatures must have appropriate uniqueness constraints.

Add migrations.

Add database tests covering:

- creating a user
- creating a wallet
- following a trader
- duplicate source transaction
- duplicate copy-trade event
- foreign-key behavior
- transaction rollback

Run all tests and migrations.

Do not implement blockchain listeners or trade execution yet.
