==================================================
PRODUCT
==================================================

The application allows users to:

1. Connect/authenticate their Solana wallet.
2. Discover wallets/traders they want to follow.
3. Follow a selected trader wallet.
4. Configure copy-trading settings.
5. Monitor the followed trader's on-chain transactions.
6. Detect relevant trades.
7. Convert the detected trade into a copy-trade instruction.
8. Execute the trade on behalf of the user only after explicit authorization.
9. Track execution status.
10. Show trade history, P&L and system status.

The system must eventually support MANY users and MANY followed wallets.

==================================================
SECURITY
==================================================

This is a financial/blockchain application.

Security is critical.

Never:

- store users' private keys in plaintext
- log private keys
- log seed phrases
- expose secrets to frontend
- hardcode API keys
- trust client-provided blockchain state
- blindly execute transactions

All secrets must come from environment variables or a secure secret-management mechanism.

Wallet ownership must be cryptographically verified using wallet signatures.

Every trade execution must have server-side validation.

Validate:
- token addresses
- wallet addresses
- amounts
- slippage
- transaction parameters
- authorization
- user configuration

Implement protections against:
- replay attacks
- duplicate trade execution
- malicious input
- unauthorized execution
- race conditions
- excessive requests

==================================================
COPY TRADING SAFETY
==================================================

A copied trade must NEVER be executed twice because of:

- duplicate websocket events
- RPC retries
- worker retries
- application restart
- queue redelivery

Use idempotency keys / unique constraints / processed transaction tracking.

Example:

source wallet
+
source transaction signature
+
user
=
unique copy-trade event

The same event must produce at most one execution.
