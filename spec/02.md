PHASE 0 — REPOSITORY AUDIT & ARCHITECTURE

Do NOT implement the complete application.

First inspect the existing repository.

Determine:

1. Current frontend framework
2. Current backend framework
3. Programming language(s)
4. Package manager
5. Existing database
6. Existing ORM
7. Existing queue system
8. Existing Solana libraries
9. Existing authentication
10. Existing Docker configuration
11. Existing environment configuration
12. Existing tests
13. Existing linting/type checking
14. Existing CI/CD configuration

Then:

A. Create an architecture document:

docs/architecture.md

Include:

- system overview
- component responsibilities
- request flow
- blockchain event flow
- copy-trading flow
- database responsibilities
- queue responsibilities
- worker responsibilities
- failure/retry strategy
- scaling strategy
- security boundaries

B. Create/update:

.env.example

Never put real secrets in it.

C. If the current project structure is poor, propose a better structure.

IMPORTANT:
Do not make large architectural changes yet.

At the end provide:

- current architecture
- proposed architecture
- problems found
- files that should be changed in future phases
- recommended next phase

Do not implement future phases.

Run existing tests/type checks/lint if available.
