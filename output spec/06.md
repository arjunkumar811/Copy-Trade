- Added database-backed followed-trader store methods with parameterized SQL.
- Added user ownership predicates to every list, delete, and settings mutation query.
- Added reactivation behavior for following a previously removed trader.
- Kept trade execution, blockchain listeners, and queues out of this phase.

## Authorization Design

Every followed-trader operation first authenticates the bearer session. Database mutations include both the followed-trader ID and `follower_user_id`, so knowing another user's ID cannot modify that user's relationship or settings. Missing or unauthorized records return the same not-found behavior rather than exposing ownership details.

## API Endpoints

- `POST /followed-traders` with `{ "traderWalletAddress": "..." }`
- `GET /followed-traders`
- `DELETE /followed-traders/:id`
- `PUT /followed-traders/:id/settings`

Settings use JSON fields `enabled`, `fixedAmount`, `balancePercentage`, `maxTradeAmount`, `maxDailyLoss`, `maxSlippageBps`, `allowedTokens`, and `blockedTokens`.
